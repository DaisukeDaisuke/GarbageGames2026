# 実装と検証範囲

## レビューへの対応

- 100件の契約JSONと199解法fixtureを収録し、実際の状態遷移と無料検品で成立を検証。
- `decision_signature` と、識別子を除く判断構造の重複監査を生成。署名100、構造100。解除11、設定17、アプリ15、更新11、複合25、復旧13、通信禁止8件。これは面白さを100種類実測したという意味ではありません。
- 権限3種類、保持内容、消去・通信などの禁止履歴を別々に保持。復元しても過去の違反は消えません。
- 最初の2台は研修、その後は5件で一周を修了。再就職後は研修を繰り返しません。開始時の信用の紹介状はD・C・B・Aへ順番に各10SPで取得でき、次の就職時の信用だけを上げます。技能がなくても納品による昇格は可能で、初期信用を上げても一周の通常納品は5件です。
- 物語の電話は全10話。初周は研修2台を含む実納品3・4・5・6件目で第1〜4話、再就職後はその後の実納品2件ごとに第5〜10話が届きます。初周の主案件5件目に届くCALL06は転職・技能・軍資金・信用紹介状の案内です。旧セーブで条件をまとめて満たしても、次の物語は追加の納品まで待ちます。復旧案内・研修・昇格の電話を優先し、再就職のお祝いは周回ごとに一度です。
- 支援で受け取ったFolioOS用SDと写真簿F10のUSBは実際の画像の端子位置に8方向の座標を合わせました。挿入と抜き取りの判定も同じ位置を使います。
- 初期$400から、管理者USB・外部画面と正規サービスを使う最初の3台の経路では$711になります。後半の投資の面白さは利用者のプレイ確認が必要です。
- RTAは任意計測。工房のPC内で開始・停止・ラップ記録と条件の書出しができます。
- 机と壁の背景、実物のPCへ寄るカメラ、8方向端末、形状別の穴と媒体、別部品の電話・受話器を実装。追加機材は右側のスライドメニュー。
- 初回は電話だけを表示し、説明に合わせてPC・媒体を開放。会話終了から最初の契約へ自動接近し、受注後の電話でUSBを使う目的とKomaOSでの作業を説明します。端末への接近は直接クリック1操作。観察レンズは旧セーブ互換用の定義のみ残し、画面には出しません。
- 電話会話は画像生成の枠と右側の人物、左側の本文。受注と作業中の案内には専用に画像生成した短縮版の枠を使用します。人物の頭は枠上端から少しはみ出します。
- Canvas文字はページから継承したブラウザ既定のフォントファミリーを使い、特定フォントを指定しません。契約の成功条件は確認項目・成功条件・現在・判定の表で表示します。
- 内部コードは表示名対応表で変換。媒体の用途、OS、対応版、形状を表示し、工程候補も日本語の操作列に変換。

## エンジン選択

標準Canvas 2D + JavaScript ES Modulesを採用。机上で数十個の物体を動かす規模と、静的Pages配置・単独ビルドに適しています。生成スプライトを8方向に切り替え、当たり判定・差込座標とカメラはコードで管理します。WebAssemblyや外部ゲームエンジンは導入していません。立体剛体シミュレーションではなく、2Dの持ち上げ・移動・差込操作です。

## 自動検証

ビルドはNode標準test runnerを使用。100案件199ルート、4つのSEEDで研修2台と通常5件の周回、権限の独立、互換性、履歴条件、課金の一度性、原子的な保存と破損回復、複製・買い取り・PoC譲渡・退職繰越、工程の試算と再実行を検証します。

ブラウザでは電話から初期物が現れる段階、PCへの接近、電話部品とコード接続、会話枠と人物の位置を確認しました。最終の操作・見た目のデバッグは利用者へ引き継ぎます。仕様書のT01〜T52・エンジン比較EG01〜EG06をすべて実施済みとはしていません。

## 実装上の範囲

候補比較の技能は収録済みの有限な解法候補を現在状態で再検証します。全操作の完全探索ではなく、最小費用・最短手順の保証はありません。工程の仮置きは実際の遷移モデルを独立コピーで動かすため、本番の資金や履歴を変更しません。

端末の向き画像は画像生成による8枚で、連続3Dモデルではありません。画面・穴の座標は機種ごとの定義と補正値を使います。全800方向を人の目で個別に調整したとはしていません。

GitHubの既存4作品を含む統合ビルドはこの追加用ZIP単体では実行できません。このゲームの単独ビルドを検証対象としています。
