# 邪魔すぎる花火メモ帳
文字を打つと本文の上に花火が開き、改行すると大きな花火が連発するメモ帳です。ページの公開先は `/Garbage2026/fire/` を想定しています。
## そのまま配置する
生成済みの `index.html` が完成したページです。GitHub Pages の公開対象に `fire/index.html` として配置してください。CSS、JavaScript、音の生成処理、仕様書は HTML に含まれています。外部 CDN、フォント、画像、音声ファイルの取得や、npm パッケージのインストールはありません。
GitHub Pages のリポジトリ名が `Garbage2026` の場合、公開成果物の `fire/index.html` が `/Garbage2026/fire/` に対応します。成果物の中へ `Garbage2026/` をもう一段追加する必要はありません。
## 編集後にビルドする
`src/` 内の HTML、CSS、JavaScript を編集したら、次のコマンドで `fire/index.html` を更新できます。実行するディレクトリに依存せず、スクリプト自身の位置から入力ファイルを読みます。
```sh
sh fire/build.sh
```
出力先を指定するときは、次のようにします。指定したディレクトリに `index.html` を生成し、同じディレクトリにある他のファイルは保持します。
```sh
sh fire/build.sh --output-dir _site/fire
```
ビルドは `sh`、`awk`、標準的なファイル操作コマンドだけで動きます。Node.js、Python、npm は使いません。入力ファイルや埋め込みマーカーに問題があると失敗し、既存の完成ファイルを維持します。
## GitHub Actions に組み込む
既存サイト全体のビルド後、公開成果物のアップロード前に、次のステップを追加してください。`_site` は既存の公開ディレクトリ名に合わせます。完成したサイト全体をアップロードする既存処理はそのまま利用します。
```yaml
- name: Build the fireworks notepad
  shell: sh
  run: sh fire/build.sh --output-dir _site/fire
```
追加ステップのサンプルは `examples/github-pages.yml` にもあります。このファイルは既存 workflow の `steps` に組み込む断片です。リポジトリ直下の `fire/` をソース配置として想定しています。
## 操作
|操作|動作|
|---|---|
|文字を入力|カーソル付近の火花に続いて花火が開きます。|
|改行|大きな花火が順に開きます。日本語変換の確定だけでは改行用の連発を出しません。|
|連続入力|花火と残光が重なります。入力を止めると数秒で静まります。|
|10コンボ以上|コンボ数が本文の上に大きく出て、確定入力のたびに色が変わります。|
|30・60・90…コンボ|8秒間のターボが始まり、打上げの数と勢いが増えます。|
|にぎやか・邪魔・祭り|常時表示のボタンで演出量を切り替えます。初期値は「邪魔」です。|
|音のボタン・音量|音のオン・オフと音量を別々に操作します。初期音量は 35% です。|
|演出の一時停止|画面の花火を消し、メモを読み返せます。編集は続けられます。|
|書き出し|現在の本文だけを UTF-8 の `.txt` ファイルに保存します。|
|仕様書|添付された企画仕様書の全文を画面内で表示します。大きな ×、背景クリック、Escape キーで閉じられます。|
本文は標準の `textarea` で編集できます。選択、コピー、貼り付け、Undo、Redo はブラウザーの通常の操作を利用します。メモと設定はブラウザー内へ保存し、再び開くと復元します。保存できない環境では画面の保存状態に表示し、テキストの書き出しを利用できます。
コンボは文字数ではなく、確定入力・実際の改行・貼り付けの1回をそれぞれ1として数えます。日本語変換の確定は1回、長い文章の貼り付けも1回です。削除、Undo、Redo、カーソル移動では増えません。最後の確定入力から2.4秒空くとコンボはリセットされます。ターボはコンボのリセットとは別に、発動から8秒間続きます。
## 表示と入力
本文は白色です。入力欄と花火を別の描画レイヤーにし、花火の描画終了時には Canvas 全体を透明に戻します。入力欄の値や選択範囲をアニメーションから書き換えません。カーソル位置の計測用要素は画面とスクロール領域から隔離しています。
旧版で報告された入力キャンセルは、今回の検証環境では再現されていません。白文字の明示、描画順の固定、通常の Canvas 描画、透明消去、計測要素の隔離は、表示を安定させるための変更です。入力が消える原因を特定したとの意味ではありません。
画面はスマートフォン幅と iframe 内の高さに合わせて配置を調整します。利用可能な環境では `VisualViewport` の高さにも追従します。実施した確認と実機未検証の範囲は `VERIFICATION.md` に記載しています。
## 記事に埋め込む
```html
<iframe
  src="/Garbage2026/fire/"
  title="邪魔すぎる花火メモ帳"
  width="100%"
  height="560"
  style="border:0;border-radius:20px"
  allow="autoplay"
></iframe>
```
この例は高さ560pxで、同じサイトの `/Garbage2026/fire/` を表示します。本文・演出・設定は iframe 内に収まり、親記事のキー操作には反応しません。
## キー演出の実装
`Insert`、`Home`、`PageUp`、`PageDown`、`End`、`Delete` は、入力欄へフォーカスしているときだけ個別の演出を出します。キーの既定処理を取り消さず、ブラウザーが行った移動・選択・スクロール・削除の後に演出します。`Insert` の編集動作もブラウザーの既定に任せています。変換中はこれらのキー演出を出しません。画面内に特殊キーの案内は表示しません。
